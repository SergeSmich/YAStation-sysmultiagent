## 2. Файлы и почему так

| Файл | Роль | Решения |
| --- | --- | --- |
| `scripts/arena_watcher.py` (новый, 1072 строки) | весь канал: опрос, доверие, claim, исполнение, комментарий | Python 3.11, только stdlib + `gh` + `git` |
| `scripts/arena_watcher.example.json` (новый) | пример конфига с заглушками | живой конфиг — `.arena/watcher.json`, `.arena/` в `.gitignore` |
| `scripts/test_arena_watcher.py` (новый) | 46 тестов на фейках, без сети | `unittest`, как остальные скрипты репозитория |
| `docs/arena-command-bus.md` (новый) | роли, поток, метки, доверие, whitelist, включение, откат | один документ, без размазывания по `guide.md` |
| `AGENTS.md` | 16 строк: «Commands via Issues» + ссылка | мост остаётся основным путём, шина — дополнительный |

Ключевые решения, которые стоит проверить ревью:

1. **Одна команда — один issue.** Тело разбирается как ровно один fenced
   ```` ```json ```` блок; два блока — отказ. Неизвестные поля верхнего уровня
   (`shell`, `cwd`, `env`) — отказ, а не игнор: иначе «лишний» ключ тихо менял бы
   смысл команды.
2. **Whitelist — это код, а не конфиг.** `ACTIONS` в модуле; аргументы каждого
   действия проверяются до claim (`validate_args`). `run_tests` сверяет пакеты с
   `allow.test_package_re`, `read_log` не выходит за `allow.log_dirs`, `grep`
   ограничен `allow.grep_globs`, `deploy_check` — только `health[]` из конфига.
   Никакой склейки shell-строк: `shell=False`, argv списком.
3. **Claim до исполнения.** `oc:running` ставится, `oc:run` снимается, затем issue
   перечитывается и `sha256` тела сверяется с прочитанным до claim. Разошлось —
   `oc:failed` и комментарий «body changed»: тело issue — это и есть команда, и
   править его после проверки нельзя.
4. **Нет автоперезапуска.** `oc:running` старше `stale_running_min` (15 мин) →
   комментарий «не выполнено» + `oc:failed`. Иначе зависший `go test` крутился бы
   вечно, а «сколько уже прошло» никто не знал бы.
5. **Доверие — два условия.** `author_association` ∈ {OWNER, MEMBER, COLLABORATOR}
   **и** логин из `allowed_logins` (пустой список = ошибка конфига). Недоверенный
   автор: снять `oc:run`, ничего не исполнять и **не комментировать** — ответ
   подтвердил бы существование шины и её формат на публичном репозитории.
6. **Публикуется только то, что прошло редакцию.** Перед комментарием — `redact`
   (ключи вида `token=`/`password:`/`Authorization:`, GitHub-токены, JWT, приватные
   ключи) и `clip` (8000 байт / 60 строк). `deploy_check` публикует `label`, код и
   время ответа, но не URL: адрес станции в issue не попадает.
7. **Окружение ребёнка урезано** (`CHILD_ENV_KEEP`): `GH_TOKEN` и прочие секреты в
   `go test` не уезжают, GitHub-доступ есть только у `gh`.
8. **Один watcher на машину.** Lock `.arena/watcher.lock` (fcntl на POSIX, msvcrt на
   Windows); мягкий стоп — файл `.arena/paused`, не трогающий GitHub вообще.

Покрыто: разбор JSON (валидный/нет блока/два блока/неизвестный action/лишний
ключ/дубль ключа/плохой `id`/клип `timeout_s`/лимит тела), аргументы каждого
действия (traversal и абсолютные пути в `read_log`, пакеты вне allowlist, `glob`
вне списка, битая регулярка, `url` не из конфига), доверие (чужой логин,
`CONTRIBUTOR`, регистр логина), дедуп (`oc:running` не исполняется второй раз),
`oc:paused`, stale-`oc:running`, подмена тела между чтением и claim, полный круг
успеха и ошибки, dry-run (ни одного вызова `gh`, ни одного запуска), редакция
секретов, обрезка, разбор меток, `Config::from_dict` (пустой allowlist, плохой
`repo`, плохой regex) и загрузка самого примера конфига.

Тесты нашли два настоящих дефекта, оба исправлены до коммита:

- `_mask` маскировал **ключ**, а не значение: `token=SUPERSECRET` превращался в
  `***SUPERSECRET`. Теперь в комментарий уходит `token=***`;
- из `Authorization: Bearer <token>` выживало слово-схема и сам токен. Схема
  (`Bearer`/`Basic`/`Token`) теперь входит в маскируемое значение.

CLI прогнан вживую на фейковом `gh` (печатает `[]`), во временном конфиге:
`--check-config` → `ok`, `--once`, `--once --dry-run`, `--init-labels` → список
5 меток, `--version`, `touch .arena/paused` → `[paused]` и выход 0. Лог
`.arena/watcher.log` пишется JSONL.

### Что НЕ прогонялось (честно)

- **Реальный GitHub.** По условию задачи issues, комментарии и метки в
  репозитории не создавались: сеть до `api.github.com` в песочнице есть, но живой
  круг — за вами после merge. Значит не проверено: права токена на issues,
  поведение `gh label create --force` на существующих метках, реакция на 404 при
  снятии отсутствующей метки (код это глотает), `per_page=50` на реальной очереди.
- **Windows.** Пути с `\`, `gh.exe`/`git.exe`, UTF-8 в консоли, ветка `msvcrt` в
  `SingleInstance` — написаны, но не исполнены: песочница на Linux.
- **Живые `git`/`go`.** Действия прогонялись через фейковый runner; настоящий
  `go build`/`go test` этим каналом не запускался (Go в песочнице нет — это же
  ограничение, что и в A-0002).
- **`deploy_check` по настоящему healthz.** `probe` не вызывался ни разу: в
  песочнице нет станции. Логика статусов (2xx–3xx успех, иначе ошибка) проверена
  только чтением кода.
- **Автозапуск.** Юнит systemd / задача Планировщика в документе приведены как
  пример и не проверялись.

## 4. Как включить и как откатить

Включение (подробно — `docs/arena-command-bus.md`):

1. `cp scripts/arena_watcher.example.json .arena/watcher.json`, заполнить `repo`,
   `workdir`, `allowed_logins`, `health[].url`.
2. `python scripts/arena_watcher.py --check-config` → `ok`.
3. `python scripts/arena_watcher.py --init-labels` (один раз, нужен `gh auth login`).
4. `python scripts/arena_watcher.py --once --dry-run --verbose` — посмотреть, что
   бы он сделал, ничего не меняя.
5. `--once` вживую, затем автозапуск (systemd/Планировщик) или `--once` из cron.

Откат: остановить процесс, удалить `.arena/watcher.json` (и `.arena/watcher.lock`,
если процесс убивали), при желании снять метки `oc:*`. Кода это не касается —
issue с `oc:run` просто перестанут читаться. Git-мост и Go-код шина не затрагивает,
поэтому откат шины не влияет на обмен `L-*`/`A-*`.

## 5. Ограничения и отступления

- Очередь читается без постраничного обхода: до 50 открытых issue на метку за
  проход. Для v1 достаточно, записано в документе.
- `build` собирает `./...` в `.arena/build/` и ничего не деплоит; на машине без Go
  команда вернёт ошибку сборки — это ожидаемый ответ, а не сбой шины.
- Метка `oc:paused` описана и проверяется, но в `--init-labels` создаётся наравне
  с остальными; отдельного «глобального» pause-лейбла нет — стоп локальный
  (`.arena/paused`), потому что он не зависит от доступности GitHub.
- Шина не умеет «продолжить» длинную команду: либо уложилась в `timeout_s`, либо
  `oc:failed`. Хвост лога читается отдельным `read_log`.
