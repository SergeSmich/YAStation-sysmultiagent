## 3. Целевая компоновка окна «Агенты»

**Словами:** вкладка «Агенты» остаётся с подвкладками Голос / Роли / Нейросети.
Сверху — `main-agent-box` и `role-call-box` (инварианты, не трогать). Над
карточками ролей — ряд чипов: имя роли + статус готовности (из
`paintRoleReadiness`); клик по чипу = выбрать эту роль как `main_agent`
(используем тот же путь сохранения, что select + «Сохранить основную модель»).
В каждой карточке роли добавляется спойлер «Диалог»: поле вопроса, кнопка
«Спросить» (POST `llm/ask` с provider/model роли), транскрипт ответа с
латентностью, кнопка «Озвучить» (если у роли задан голос — `voice/test`).
«Длина ответа» — select 260/700/1400/2000 в карточке роли, кладётся в
generation parameters роли. System prompt и его сохранение остаются как есть
(один saveButton на карточку — не дублировать их отдельную кнопку).

**ASCII-схема:**

```
┌─ tabs:  Маршрутизация │ Агенты │ Станция │ Сисадмин │ Журнал
├─ subtabs:  Голос │ Роли │ Нейросети
├─ main-agent-box:  Основная модель [select]  [Сохранить основную модель] [Проверить модель]
├─ role-call-box:   голосовой вызов [enabled] [dry-run] [Сохранить голосовой вызов]
├─ чипы ролей:  [роль1 ●готов] [роль2 ●неготов] [+новая роль]      ← клик = основная
├─ карточки ролей (fold-card, settings-row):
│    ┌─ Имя│Нейросеть│Голос│Модель│Системный промпт│Длина ответа│…
│    │  └─ spoiler «Голосовой вызов»: callable│алиасы│greeting│Проверить│Прогнать фразу
│    │  └─ spoiler «Диалог»: [вопрос] [Спросить] → транскрипт│[Озвучить]
│    └─ [Сохранить] [Проверить модель] [Удалить]
└─ Нейросети: provider-cards (как сейчас: ключ не возвращается, saveButton)
```

**Инварианты сохраняются явно:** `main_agent` — указатель на роль (ничего
другого не становится «основным»); `role_call` — алиасы/приветствие/callable
в спойлере без изменений; ключи — только в `secrets.json`, панель показывает
только `key_set` (как сейчас); пустое поле ключа = не менять; сохранение
по карточке без перезаписи других sections.

## 4. План внедрения (6 шагов)

**Шаг 1 — Чипы ролей + мини-диалог.** `cmd/quasar-bridge/panel.js`,
`panel.css`. Критерий: на вкладке «Роли» чипы показывают все роли со статусом
готовности из `paintRoleReadiness`; клик по чипу меняет select `main-agent` и
сохраняет; «Спросить» отдаёт `llm/ask` с provider/model роли и рисует
транскрипт + латентность; «Озвучить» работает, когда роль имеет голос.
Риск: клик по чипу должен проходить через тот же save-path, что «Сохранить
основную модель» — иначе appears new state.

**Шаг 2 — «Длина ответа» по роли.** `panel.js`, backend (role generation
parameters). Критерий: select 260/700/1400/2000 сохраняется с ролью;
сериализация role не ломает существующий `role_call`/`main_agent`
(saveCard патч, partial patch). Риск:旧ые роли без числa — default 260, без
migraции.

**Шаг 3 — Оформление: токенная шкала + 12-col grid.** `panel.css`.
Критерий: `--fs-*`, `--gap-*`, `--ctl-h`, `--r6…20` определены в `:root`;
settings-row/tabs/subtabs используют их; карточки агентов — 12-col grid с
span-управлением; mobile (max-width:560px и 700px) — сворачиваются в одну
колонку. Риск: мобильная регрессия (tabs на узких экранах, `overflow-x`);
проверить 760/700/560 breakpoints по их статье.

**Шаг 4 — Светлая тема + manifest + drag-and-drop.** `panel.css`,
`panel.html`, `panel.js`. Критерий: `body.light` без несогласованных токенов
(rgba-stroke, `--card-*`, ::after акценты); `manifest.json` + иконки отдаются
с сервера; drag-and-drop меняет порядок карточек и сохраняет в localStorage
(как `mypult.*` у них). Риск: PWA-установка на https с самоподписанным
сертификатом (Chrome упирается); drag-and-drop — не ломать saveButton
(mousedown vs click).

**Шаг 5 — Станция: видимость музыки + netcheck (минимум).** `panel.js`,
`panel.html`. Критерий: карточка «Музыка» показывает текущий трек/радио +
play/pause (если включён `music_playback_enabled`); netcheck-card показывает
gateway/интернет/DNS/HTTP-задержку. Риск: зависания endpoints при остановке
музыки — показать как status, не как error.

**Шаг 6 — Сценарии/таймеры/будильники.** Следующий круг (зависит от
голосовой ветки watcher/command bus). Критерий: таймер/будильник создаётся
с расписанием `{time,days}` (как их `scenarios.py`), показывается в панели.
Риск: конфликт с `role_call` (звание фразы) — сценарии не должны перехватывать
голосовые вызовы ролей.

## 5. Что нельзя ломать (список инвариантов)

1. `role_call` — алиасы, приветствие, `callable`; голосовая ветка
   (`voice_daemon`: сценарий → переключение LLM/чата → интенты → LLM).
2. `main_agent` — указатель на роль; пустое значение = `llm_*` (деплой без
   поля ведёт себя как раньше).
3. Секреты — только `secrets.json` 0600; панель показывает только `key_set`;
   пустое поле ключа = не менять; ключи не в GET.
4. Деплой — PowerShell/update mechanism; GitHub-Releases-апдейтер не трогать.
5. Голосовая ветка — не добавлять переключение сценариев в role_call; «стоп»
   остаётся текстовой директивой, не глушением звука; нарезка 1700 символов.
6. Атомарная публикация — Engine publish (revision), settings-patch partial.

## 6. Что проверять на живой станции вручную

1. Вкладка «Агенты»: чипы показывают все роли; клик по чипу меняет
   `main_agent`; «Сохранить основную модель» не дублирует state.
2. Мини-диалог: «Спросить» → ответ в транскрипте + латентность; «Озвучить»
   читает голосом роли.
3. Длина ответа: 260/700/1400/2000 — роль отвечает длиной до выбранного
   значения; дефолт 260 для старых ролей.
4. Оформление: светлая тема (◐) без несогласованных токенов; мобильная
   версия (560px) — tabs сворачиваются, карточки в одну колонку.
5. PWA: манифест отдаётся; установка на https с доверенным корневым
   сертификатом.
6. Drag-and-drop: порядок карточек сохраняется после refresh.
7. Сценарии/таймеры (после шага 6): создание будильника → срабатывание →
   журнал; перехват голосового вызова ролей не происходит.
