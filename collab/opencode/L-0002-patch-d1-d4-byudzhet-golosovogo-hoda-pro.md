## Задача

Принять A-0001 и реализовать только дефекты **D1–D4** одним связным изменением:
убрать синхронное ожидание из голосового хода, включить прогресс в ветке гейта и
сделать асинхронный отчёт о результате для колонки.

D5–D11 в этом круге не трогать.

## Что именно сделать

### D1. Бюджет хода вместо ожидания

- `cmd/quasar-bridge/sysadmin_voice.go:17,151,155,290`.
- Ввести `voiceTurnBudget = 12 * time.Second` — общий бюджет на весь голосовой
  ход, отсчёт от начала хода (в `nativeRequest` положить `startedAt`, прокинуть
  в гейт).
- `voiceResultWait` как константу убрать; ожидание = остаток бюджета.
- Если остаток меньше 2 с — не ждать вовсе.
- `voiceDecisionBudget = 2 * time.Second` на `DecideScope` + `grant` +
  `planCoversStep`.

### D2. Прогресс в ветке гейта

- `internal/bridge/native.go:915–916`: стартовать `n.progress(p)` до первого
  ожидания, как это уже сделано для резолвера на `:944`.
- `progress.go:49–53` уже умеет `p.gated` — использовать это, не дублировать.
- Если `local_progress.enabled = false`, прогресс не запускать, но ответ всё
  равно должен укладываться в бюджет D1 (12 с).

### D3. Убрать `AskAgent` из голосового хода

- `sysadmin_voice.go:176–191,294–300`.
- Немедленный ответ: «Хорошо, делаю» / «Разрешила, выполняю» — без ожидания
  результата и без пересказа.
- `AskAgent`-пересказ перенести в асинхронную доставку (D4), бюджет 45 с
  остаётся, но вне хода.

### D4. Асинхронный отчёт для колонки

- `cmd/quasar-bridge/main.go` рядом с `:364`: зарегистрировать `Queue.OnFinish`.
- Для голосовых заявок (`ChatID == 0`) — `AskAgent` роли + запись результата в
  панель (по образцу `telegram_runner.go:206` → `Followup`).
- Для Telegram (`ChatID != 0`) поведение не менять, двойного отчёта быть не
  должно.
- Если заявка завершилась ошибкой — отчёт обязан содержать код возврата и
  первые строки вывода (в рамках того, что уже есть в `ExecResult`; D5 не
  исправлять, но не терять то, что пришло).

   ровно один отчёт Telegram и ноль голосовых.
