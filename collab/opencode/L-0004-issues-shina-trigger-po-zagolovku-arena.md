## Изменение триггера (главное)

Arena не может пометить issue. Поэтому команда определяется по **заголовку**:

- issue открыт;
- автор доверенный (`author_association` + `allowed_logins` — как сейчас);
- заголовок соответствует `^\[CMD\]` **или** `^oc:\s*CMD-[0-9]{4,6}\b`;
- в теле ровно один ```json блок с командой;
- нет меток `oc:running`, `oc:done`, `oc:failed`, `oc:paused`.

Метка `oc:run` остаётся **альтернативным** триггером для оператора и обратной
совместимости: если она есть, issue обрабатывается как раньше, независимо от
заголовка.

Состояние по-прежнему пишет только watcher (`oc:running` → `oc:done`/`oc:failed`).
Arena эти метки не ставит и не снимает. В документации явно написать: Arena
создаёт issue с заголовком `[CMD] ...`, читает результат через
`gh issue view <n> --comments`, **не** пытается ставить метки, комментировать или
закрывать — у её токена нет Issues: write.

После результата watcher **закрывает issue** (новый параметр
`close_after_result`, по умолчанию `true`), чтобы очередь не забивалась. Если
`false` — оставляет открытым. Закрытый issue Arena читает тем же `gh issue view`.
