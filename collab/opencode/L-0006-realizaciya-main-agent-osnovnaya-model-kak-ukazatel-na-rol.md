# Реализация main_agent: основная модель как указатель на роль

Основание: A-0005 (`5c4ec51`), решения §2 и порядок §4 «L-0006».
Круг — **только код и панель**. Ответ — коммит с кодом + отдельный коммит `A-0006`
с отчётом (как в A-0002/A-0004: код не содержит путей `collab/`).

## Что сделать (по A-0005 §4)

1. `cmd/quasar-bridge/config.go`: `MainAgent string` рядом с `LLM*`; `validateMainAgent()`
   — роль существует, проходит валидацию ролей, модель непустая; вызов из общей
   `validate`. `resolveLLM` **не менять**.
2. `internal/bridge/engine.go`: `answerer()` над `atomic.Pointer[Completer]`,
   `SetLLM(Completer)`; все шесть мест чтения `e.LLM` — на аксессор;
   `Guard` и `safety.go` — через корневой клиент (не через роль).
3. `cmd/quasar-bridge/agents.go`: `buildMainAnswerer` — `resolveLLM(role)` + ключ +
   промпт роли + обёртка в `assistant.Agent` при `assistant_tools.enabled`;
   **без** `sysadmin`/`peers` toolset — это инвариант, не флаг.
4. `cmd/quasar-bridge/main.go`: `engine.SetLLM(main)` вместо жёсткого `LLM:`;
   корневой клиент остаётся для `Guard`, `Home.Planner` и при пустом `main_agent`;
   `applySettingsConfig` пересобирает основной ответчик, `slog.Info("main_agent_ready", …)`.
5. `cmd/quasar-bridge/settings.go`: `settingsPatch.MainAgent *string`, обработка в
   `applySettingsPatch`, `main_agent` + разобранный таргет в `settingsSnapshot`,
   `warnings[]` (`agent`, `model`, `provider_model`) при `agent.model != provider.model`.
6. Панель: `panel.html` + `panel.js` — карточка «Основная модель» первой в
   «Агенты → Роли» (не в «Нейросети»): список «Как `llm_*` (по умолчанию)» + роли,
   под ним разбор `провайдер · модель · ключ: есть/нет · промпт: роль/общий`,
   кнопка проверки — существующая `apiLLMCheck`; предупреждения: `sysadmin`-роль
   («инструменты не наследуются»), пустой промпт, длинный промпт. В «Маршрутизации» —
   строка-подсказка у маршрута `llm`: «→ основная модель: `helper`» / «→ `llm_*`».
   Чип «модель от другого провайдера» + кнопка «взять модель провайдера» (явное
   действие оператора, без автоочистки).
7. Тесты: пустой/неизвестный `main_agent`, пустая модель роли; `-race` на `SetLLM`
   во время `Fallback`/классификатора; hot-apply через `applySettingsPatch` (клиент
   заменён, `main_agent` в файле); `sysadmin`-роль без toolsets; `warnings` при смене
   провайдера.
8. `docs/guide.md` (операторская часть «Основная модель») и `docs/design.md`
   (раздел про маршрут `llm`).

## Критерий готовности

- Пустой/отсутствующий `main_agent` — поведение **идентично** текущему: старые тесты
  проходят без правок ожиданий.
- `main_agent: "<роль>"` — `llm`-ход идёт клиентом роли; классификатор использует
  того же клиента, но **свой** системный промпт (проверяется тестом на подменённом
  клиенте).
- Роль с `sysadmin:true` как основная: в собранном клиенте нет `sysadmin`/`peers`.
- Hot-apply из панели меняет ответчик без рестарта и пишет `main_agent` в файл;
  `GET` панели не отдаёт ключи.
- Неизвестная роль или пустая модель — `400` при сохранении и отказ загрузки конфига;
  **никакого** тихого отката на `llm_*`.
- `go build ./...`, `go vet ./...`, `go test ./internal/bridge ./internal/sysadmin ./cmd/quasar-bridge`
  — зелёные. Если в песочнице нет Go 1.27.3, честно написать это в A-0006 и перечислить,
  что должен прогнать оператор (включая `-race`).

## Ограничения

- Механизм обновления на PowerShell не менять; деплой не делать.
- Секретов в `config.json` и в `GET` панели нет; ключи не печатать.
- Три существующие роли не пересоздавать, их поведение по умолчанию не менять.
- Никаких новых сущностей «основная модель»: только `main_agent` + роль.
- `role_call`/`greeting`/`callable` — **не** в этом круге (L-0007).
