## Задача

Провести вдумчивый разбор проекта **MidiPult** (MIT, локальная веб-панель для рутованной Станции Миди) и вернуть **план разумного совмещения** его лучших сторон с нашим `quasar-bridge`. Интересует в первую очередь **окно агентов**, затем оформление и остальные экраны. Итог — файл `A-0008` с разбором, таблицей «берём / не берём / отложить» и упорядоченным планом внедрения с проверяемыми критериями. Код в этом круге не нужен.

Их «окно агентов» — вкладка **«Нейросеть»** (слова «агент» в UI нет):

- ряд **чипов-профилей** `#llmProfiles` (`display:flex; flex-wrap:wrap`), клик = переключить активный профиль;
- **чат-бар**: `‹ Чат 1 ›`, `+ чат`, переименовать, удалить;
- «Длина ответа»: 260/700/1400/2000 (потолок, не приказ);
- «Характер ответов (system prompt)» + отдельная кнопка сохранения;
- сетка `llm-grid` (`repeat(auto-fit,minmax(170px,1fr))`): Провайдер, Название профиля, Модель, Своя модель, Base URL, API-ключ (**только `key_set`**, значение не возвращается), тумблер «Голосовые вопросы»;
- кнопка «Сохранить» на карточку, статус рядом; ниже — поле вопроса, «Спросить», «Озвучить», транскрипт.

API `llm.py`: `GET ?info=1`; `POST {enabled}`, `{profile_id,name,provider,model,base_url,key}`, `{activate}`, `{delete}`, `{prompt}`. Конфиг `/data/mypult/llm.json` 0600, чаты `chats.json`, история 20 сообщений.

Голос у них: порядок «сценарий → переключение LLM/чата → встроенные интенты → LLM»; дедуп одинаковых фраз 30 с; перед своим ответом `sendText «стоп»` отменяет TTS Алисы (не глушит звук); длинный ответ режется по ~1700 символов и читается частями.

Архитектурные приёмы: `state_daemon` на 127.0.0.1:8057 отдаёт `/state` за ~5 мс и ~0,5 КБ, `?full=1` — ~21 КБ; разделы грузятся лениво при открытии вкладки; CGI пишут JSON атомарно; PIN проверяется на сервере (без куки отдаётся только страница входа, прямой `/index.html` — 403); обновление из панели качает архив только с хостов GitHub по https, сверяет SHA-256, делает бэкап и откат, воркер живёт в отдельной сессии.

### Наш проект (`quasar-bridge`)

- Go-бинарь на станции; панель на 8444/8445, healthz на 8443 только по localhost.
- `cmd/quasar-bridge/panel.html` — 410 строк / 28 КБ, `panel.css` — 524 строки / 23 КБ, `panel.js` — 3282 строки / 153 КБ.
- Вкладки: Маршрутизация, Агенты (подвкладки Голос / Роли / Нейросети), Станция, Сисадмин, Журнал.
- API: `/api/panel/{session,state,voice,settings,wake/dictionary,turns,logs,metrics,update,backup,station/volume,sysadmin/*}` + POST `llm/{test,models,detect,check,ask}`, `voice/test`, `password`, `routing/test`.
- Опрос: `state`+`turns` раз в 5 с, логи 15 с, метрики 10 с; при `document.hidden` опрос остановлен.
- Инварианты проекта: `main_agent` — указатель на роль; `role_call` (алиасы, приветствие, `callable`); роль с `sysadmin:true` как основная — без toolset `sysadmin`/`peers`; ключи только в `secrets.json` 0600 и никогда в GET; сохранение по карточке; пустое поле ключа = не менять.

Что у нас **уже взято** из MidiPult (v0.7.x): дизайн-токены, aurora-фон, капсульные табы, градиентные слайдеры. Атрибуция есть: комментарий в начале `panel.css`, `docs/licenses/MIDIPULT-LICENSE.txt`, запись в `THIRD_PARTY_NOTICES`. То есть речь не о первом переносе, а о следующем шаге.

### Черновой план, который нужно раскритиковать

- **Этап 1 — окно агентов.** Чип-строка над «Роли» (имя роли, нейросеть, модель, статус готовности; клик = сделать основной `main_agent`); компактная панель основных действий («Основная модель», «голосовой вызов», «Проверить модель») в одну строку, детали в спойлере; карточка «Проверить в диалоге» по образцу их чат-бара: поле вопроса, «Спросить», транскрипт, «Озвучить» — на существующем `llm/ask`.
- **Этап 2 — оформление.** Ввести их шкалу токенов (`--fs-*`, `--gap-*`, `--ctl-h`, `--r6…20`); перейти на 12-колоночную сетку карточек с явными брейкпоинтами; добить светлую тему; `manifest.json` + иконки (у нас есть сертификат, PWA установится); drag-and-drop порядка карточек с сохранением в `localStorage`.
- **Этап 3 — другие экраны.** «Звук» на вкладке «Станция» (текущий трек/радио, play/pause/next/prev, громкость, список радио); «Система» — netcheck (шлюз/интернет/DNS/HTTP-задержка) рядом с метриками; «Сценарии» — расписание таймеров и будильников с шаблонами.
- **Не берём:** Python CGI, отдельный `state_daemon`, их PowerShell-деплой, GitHub-Releases-апдейтер (у нас свой механизм по решению оператора), UDP-discovery для Android, VPN/BT/Zigbee.
