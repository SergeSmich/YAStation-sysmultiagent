# Инструкция оператора

Коротко: **слева opencode — руки, справа Arena — голова по вызову.** Между ними
нет чата, только файлы в git. Всё, что должно пережить сессию, лежит в
`STATE.md` и в коммитах, а не в истории переписки.

## 1. Кто где

| | opencode (слева) | Arena (справа) |
| --- | --- | --- |
| Роль | руки: файлы, git, ssh, панель, сборка, деплой, диагностика | голова по вызову: архитектура, ревью, крупный код, разбор upstream |
| Помнит | сессию, но контекст восстанавливает из `STATE.md` и git | ничего: контекст даёт только файл задачи `L-*` |
| Может | всё, что разрешено правилами ниже | читать/писать файлы в своей ветке, коммитить, пушить ветку, создавать issue |
| Не может | пушить и деплоить без твоего слова | запускать Go, трогать станцию, ставить метки, комментировать и закрывать issue (403) |
| Лимит | — | 180 с между пингами, 4/час, 8/сутки |

Связь: я пишу `collab/opencode/L-NNNN-*.md` → пинг одной строкой в чат Arena →
Arena коммитит `collab/arena/A-NNNN-*.md` в свою ветку → я читаю, применяю,
прогоняю. Пересказывать друг другу «что мы обсуждали» бесполезно: Arena этого
не видит. Всё нужное должно быть в файле задачи.

## 2. Правила, которые действуют всегда

1. **Push — только по явному «да».** Исключение: файлы моста (`collab/opencode/L-*`,
   `collab/runs/*.json`) пушу сразу — иначе Arena их не прочитает.
2. **Деплой — только по слову «Выкатить»** для конкретной версии, после прогона
   на станции. Сборка и тесты — не разрешение на выкат.
3. **Секреты** (ключи API, токен бота, пароль хоста) не попадают в чат, в git,
   в issue и в `config.json`. Живут только в `secrets.json` (0600) и в полях
   `secret-input` панели. Файл целиком я не читаю.
4. **Issue публичны навсегда:** без адресов, серийников, логинов и путей к дому.
5. **Квота Arena** — закон: если governor сказал «нет», это пауза, а не повод
   обойти. Не дублирую пинг «на всякий случай».
6. **Источник истины — прогон и лог**, а не текст модели. Отчёт Arena без
   компилятора/устройства считается гипотезой.
7. **Удаление и изменение системных параметров** — только с твоим разрешением.
   Диагностику, чтение логов и сборку делаю без вопросов.
8. **Механизм обновления** (PowerShell) не меняю без отдельного решения.
9. **GitHub Actions не включаем**, план самоулучшения (PR/CI) на паузе.

## 3. Как поставить задачу Arena

Скажи одной фразой: «Отдай Arena: <что сделать>». Полезно добавить критерий:
«…и чтобы тесты были зелёные» / «…только разбор, без правок».

Дальше делаю я:

1. пишу `L-NNNN` с целью, контекстом, критерием готовности и ограничениями;
2. коммичу и пушу файл задачи (это не код);
3. отправляю пинг в чат одной строкой и записываю квоту;
4. жду коммит `A-NNNN`, читаю его, применяю к своему дереву;
5. прогоняю сборку/тесты и только потом докладываю тебе.

Ты на этом шаге не делаешь ничего. Если Arena задаёт встречный вопрос, он
приедет как `A-*` с вопросом в конце — увидишь в моём отчёте.

Что стоит отдавать Arena: разбор чужого кода, проектирование, большие патчи,
сравнение версий upstream. Что не стоит: «поправь одну строку» (дешевле сам),
«запусти на станции» (у неё нет доступа), «посмотри логи» (их нет в git).

## 4. Второй канал: команды через GitHub Issues

Нужен, когда ты хочешь дёрнуть проект без меня: с телефона, из браузера, из
другого чата.

- **Заголовок** issue — триггер: `[CMD] git_log n=3` или `oc: CMD-0002 ...`.
  Регистр не важен, метки не нужны.
- **Тело** — ровно один блок:

  ````text
  ```json
  {"id":"CMD-0007","action":"git_log","args":{"n":5},"timeout_s":60,"note":"зачем"}
  ```
  ````

- **Действия:** `git_status`, `git_log`, `run_tests`, `build`, `read_log`,
  `grep`, `deploy_check`. Произвольных команд, push, деплоя и записи файлов
  там нет принципиально.
- **Что происходит:** watcher раз в 60 с забирает issue, ставит `oc:running`,
  исполняет, пишет комментарий `oc:result`, ставит `oc:done`/`oc:failed` и
  закрывает issue. Читать ответ: `gh issue view <n> --comments`.
- **Метка `oc:run`** — ручной триггер, если заголовок обычный. Arena её не
  ставит (у неё нет прав); для неё работает только заголовок.
- **Пауза:** создай файл `.arena/paused` — watcher перестанет забирать команды,
  но продолжит жить. Снять паузу — удалить файл.
- **Если watcher не запущен** — шина просто молчит. Станция, мост и панель от
  неё не зависят.

## 5. Автозапуск и управление watcher

Задача Планировщика `ArenaWatcher` (запуск при входе в систему, от твоего
пользователя — иначе `gh` не найдёт токен).

```powershell
# поставить / переставить
powershell -ExecutionPolicy Bypass -File scripts\arena_watcher_task.ps1 -Action register
powershell -ExecutionPolicy Bypass -File scripts\arena_watcher_task.ps1 -Action register -Force

# посмотреть (состояние, последний запуск, pid, пауза)
powershell -ExecutionPolicy Bypass -File scripts\arena_watcher_task.ps1 -Action status

# запустить сейчас / остановить / убрать совсем
powershell -ExecutionPolicy Bypass -File scripts\arena_watcher_task.ps1 -Action run-now
powershell -ExecutionPolicy Bypass -File scripts\arena_watcher_task.ps1 -Action stop
powershell -ExecutionPolicy Bypass -File scripts\arena_watcher_task.ps1 -Action unregister
```

Разово, руками (из `F:\Projects\Midi\bridge\arena`):

```powershell
python scripts\arena_watcher.py --check-config      # проверить конфиг
python scripts\arena_watcher.py --once --dry-run    # показать, что бы выполнил
python scripts\arena_watcher.py --once              # один круг по-настоящему
```

Лог: `.arena\watcher.log` (JSON, по строке на событие). Конфиг:
`.arena\watcher.json` (в git не попадает).

**Полный откат шины:** `-Action unregister`, затем удалить `.arena\watcher.json`.
Git-мост, Go-код, станция и панель при этом не меняются — откат ничего не ломает.

## 6. Два чата в одном окне: как этим жить

- **Слева** — opencode. Это рабочий инструмент: он правит файлы, ходит по ssh,
  собирает, выкатывает. Одна сессия = один заход; сессии привязаны к папке.
- **Справа** — Arena. Это подрядчик в отдельной комнате: у него своя ветка и
  свой ноутбук без доступа к твоим машинам. Он не помнит вчерашний день.
- **Не пересказывай между ними.** Если нужно, чтобы Arena знала контекст — он
  идёт в файл задачи. Если нужно, чтобы я знал её вывод — он лежит в `A-*` и в
  `STATE.md`.
- **Не пингуй дважды.** Квота 4/час: второй пинг «ты там?» съедает попытку.
  Проверка — `arena_status` (я это делаю сам).
- **Если Arena упала или ругается** — перезагружаю чат и продолжаю с той же
  задачей: она в git, потери нет.
- **Если Arena начала рефакторить лишнее** (так было с `arena_watcher.py`:
  форматтер переписал файл целиком) — правку забираю только по смыслу, шум
  выкидываю. Правило: смотрю `git show --stat`, а не сообщение «готово».

## 7. Новый проект

Скажи: «Новый проект: `F:\...` — подними мост». Дальше по чеклисту:

1. Папка проекта, `git init`, remote `origin` (и `upstream`, если проект чужой).
2. `collab/opencode/`, `collab/arena/`, `collab/runs/`, `.gitignore` с `.arena/`.
3. `collab/bridge.json`: имена веток (`local/opencode`, `arena/<сессия>`),
   квоты governor.
4. `AGENTS.md` — протокол моста (копируется из этого репозитория).
5. Ветки: рабочая `local/opencode`, ветка Arena на сессию.
6. Новый чат Arena: подключить тот же репозиторий, дать первую задачу `L-0001`
   с целью проекта.
7. `STATE.md`: цель, что сделано, что дальше, чем закончилось в прошлый раз.

Без `STATE.md` проект живёт только в истории чата — а она сжимается. Это
главная причина, по которой старый проект «забывает» контекст.

## 8. Вернуться к старому проекту

1. Открыть opencode в папке проекта (сессии привязаны к каталогу; если проект
   в worktree — `worktree_list`, потом `session_move`).
2. Сказать: «Продолжаем <проект>: прочитай `STATE.md` и скажи, где мы».
3. Я читаю по порядку: `STATE.md` → `git log --oneline -10` → `git status` →
   состояние моста (`collab/bridge.json`, последние `L-*`/`A-*`) → квоту.
4. Продолжаем с раздела «Next Move» в `STATE.md`, а не с воспоминаний.
5. Если проект жил давно: сначала проверяю, что станция/сервис на месте
   (диагностика без разрешений), потом уже правки.

Фраза-пароль для тебя одна: **«продолжаем <проект>»** — остальное соберу сам.

## 9. Чеклисты

**Перед выкаткой**

- [ ] `go build ./...` и `go test` по затронутым пакетам — зелёные;
- [ ] версия поднята, в `STATE.md` записано, что в ней;
- [ ] известен откат (прошлый тег/артефакт);
- [ ] прогон на станции: голос, панель, журнал — без «Ошибка Алисы»;
- [ ] сказано «Выкатить».

**Раз в день (или после долгой паузы)**

- [ ] `-Action status`: задача Running, последний запуск свежий;
- [ ] `.arena/paused` нет (или есть — если так задумано);
- [ ] квота Arena не выедена;
- [ ] `STATE.md` отражает реальность.

**Если что-то сломалось**

1. Создать `.arena/paused` — шина перестаёт исполнять команды.
2. Посмотреть `.arena\watcher.log` (последние 20 строк).
3. Откат шины — `-Action unregister`; откат моста — как в `docs/arena-command-bus.md`.
4. Станция и панель от шины не зависят: их откат — отдельный, по версиям.

## 10. Чего я не делаю без тебя

- не пушу код и не создаю PR;
- не деплою и не перезапускаю сервисы на станции;
- не удаляю файлы, ветки, задачи и метки;
- не меняю системные параметры (автозапуск, реестр, сеть, сертификаты);
- не читаю `secrets.json` целиком и не печатаю ключи;
- не включаю GitHub Actions и не запускаю самоулучшение;
- не обхожу квоту Arena и не «дожимаю» запрет governor.
